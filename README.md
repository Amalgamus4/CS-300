# CS-300
DSA: Analysis and Design

    What was the problem you were solving in the projects for this course?
      We were trying to learn about the various types of data structures available and how to apply them to a problem. The problem in question was reading in course information for a university (from a .csv file), including course numbers, titles, and prerequisistes. We then had to search for specific courses to print and print out a list of all courses in alphanumeric order. We were also tasked with data validation, ensuring that incomplete data was not added. This included courses with a prerequisite that did not exist in the course list and courses that were missing titles.
    
    How did you approach the problem? Consider why data structures are important to understand.
      I approached the problem from the view of the end user, trying to determine which data structure would provide the best user experience. Applying the correct data structure to a problem is a cruicial piece of the problem solving puzzle. Without an appropriate data structure, it could be very difficult to find the information you need when searching, or it might be very difficult to sort the data for printing. I also used the methods taught in the course to properly pseudocode before diving into actually coding. This sped up the coding process immensely.
      
    How did you overcome any roadblocks you encountered while going through the activities or project?
      Most of the roadblocks I encountered involved using the proper syntax or using the right tool from an existing library. Looking up the documentation for the libraries and tools helped to clarify how to use them properly. At one point, I also stuggled with my parsing routine. I had written psuedocode that did not translate well into actual code and I had to spend some time searching for an alternative solution. Ultimately, I was able to find a viable path forward and completed the assignment.
      
    How has your work on this project expanded your approach to designing software and developing programs?
      Seeing the different ways to store and access data has helped me realize that there can be more than one right solution to a problem, although there may be a "better" option. I also realized the importance of pseudocode. I have used it before, but only or small projects where it seemed like an unnecessary step. On a larger project, however, it made it much easier to start programming. This was espcially true when it came to the file parsing routine, even given the trouble I mentioned in the previous answer.
      
    How has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?
      Throughout the project, I saw the opportunity to apply modularization to the code, making functions that could be used multiple times to clean up the code. By appropriately naming variables and functions, it made it much easier to read the code and know exactly what it did. Adding comments to the code certainly helped with understanding the code, but proper naming conventions made it clear what the code actually did. Also, seeing patterns for things like how to create a binary search tree will be useful in my future programming because the basis for the tree is the same. It just needs to be adapated to the specific data I'm working with.
